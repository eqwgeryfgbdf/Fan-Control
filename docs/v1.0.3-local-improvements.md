# v1.0.3 本地改善紀錄

日期：2026-10-26（Asia/Taipei）。這是本地開發紀錄，尚未發布 GitHub Release。

## 控制服務讀值保護

- 控制服務自行每秒檢查所有正在控制的風扇，不依賴 App 的心跳來判定感測器是否健康。
- 風扇讀值、硬體模式或原本可讀的 CPU／GPU 溫度持續失效三秒時，撤銷手動控制並恢復自動；短暫失敗後恢復有效讀值會重新計時。
- 原本不支援的溫度感測器不會單獨阻擋手動控制；曾在手動期間取得有效讀值的溫度種類會納入監測。
- 恢復失敗時保留控制日誌、撤銷舊連線的心跳續期，持續重試；未完成恢復前拒絕新的手動控制。
- 將服務的連線擁有權、心跳、熱狀態與讀值檢查抽成可測試的共用邏輯。

驗證：25 項測試通過，其中新增 8 項服務行為測試，涵蓋持續／短暫讀值失效、溫度支援差異、多風扇、熱狀態、逾時、連線隔離及恢復失敗後重試。這些使用模擬硬體，未對實機注入過熱或感測器故障。紀錄：`dist/tests-v1.0.3-safety.log`。

## 服務連線與版本確認

- 已授權與可調速分開顯示。App 會檢查服務回應、協定版本、App 版本及 build，全部相符才開放手動套用。
- 舊服務的文字回應、版本不符或連線失敗都會顯示具體狀態與重新啟動入口；重新註冊後須通過連線檢查才顯示可調速。
- 服務回報控制擁有權、待恢復狀態與恢復原因。失敗或斷線只顯示「正在確認自動恢復」，不直接宣稱恢復成功。
- 自動選項在恢復成功後才切換，另顯示硬體實際模式，避免把正在編輯的手動目標當作已生效狀態。
- 本地版本改為 1.0.3、build 5；保留既有 bundle 與 helper 識別。

驗證：27 項測試通過，包含新增的版本／build／協定不符、舊服務回應及恢復狀態序列化測試。App／helper 本地編譯通過。紀錄：`dist/tests-v1.0.3-service.log`、`dist/build-v1.0.3-service.log`。

## 選單列顯示與快速調速

- 選單列可分別開關 RPM、CPU、GPU 數字及迷你走勢圖，預設顯示三種讀值。關閉數字時保留圖示，展開面板仍顯示完整資料。
- 手動面板加入 1,500／2,000／2,500 RPM 快速套用按鈕；不在目前風扇硬體範圍內的選項會省略，不會把標示值偷偷改成另一個值。
- 加入整數 RPM 輸入欄，可按 Return 或「套用轉速」確認；空白、非整數、無限值、溢位或超出硬體範圍的輸入不允許套用。保留原本每格 50 RPM 的滑桿。
- 快捷按鈕與輸入套用均要求新鮮讀值、可用服務及正常系統熱狀態，仍經由 helper 再次驗證範圍並確認硬體回讀。

驗證：29 項測試通過；新增快捷選項的硬體範圍過濾，以及輸入邊界／非法內容拒絕測試。紀錄：`dist/tests-v1.0.3-menu.log`。
